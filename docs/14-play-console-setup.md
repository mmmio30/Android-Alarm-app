# 14. Google Play Console 申請の進め方

| 項目 | 内容 |
|---|---|
| フェーズ | E（Play 公開・実装と並行） |
| ステータス | 着手前 |
| 最終更新 | 2026-09-03 |

> **この工程は実装より先に着手する。**
> 個人用デベロッパーアカウントには**公開前に 12 人 × 14 日間のクローズドテスト**が必須で、
> ここがリリースまでのリードタイムを最も左右するため。

---

## 14.1 いちばん重要な事実: 12 人 × 14 日

2023 年 11 月 13 日以降に作成された**個人用**デベロッパーアカウントには、
本番公開の前に次の要件が課される。

| 項目 | 内容 |
|---|---|
| テスター数 | **12 人以上**がクローズドテストにオプトイン（参加）していること |
| 期間 | **14 日以上連続**でオプトインし続けていること |
| 注意 | 14 日未満で離脱したテスターは**カウントされない** |
| 申請 | 条件を満たすと Play Console から「本番環境へのアクセスを申請」が可能になる |
| 申請時 | テストのフィードバック、アプリの情報、本番リリース準備状況のアンケートに回答する |

### ここから逆算したスケジュール

```
アカウント作成・本人確認         ┐
  （数日〜。本人確認に時間がかかる場合あり）
                                 │ 実装フェーズと完全に並行して進める
テスター 12 人の確保             ┘
        ↓
クローズドテスト用のビルドを配信
        ↓
14 日間の連続オプトイン期間  ← ここは待つしかない
        ↓
本番アクセスを申請 → 審査
        ↓
一般公開
```

**結論: MVP が完成してからアカウントを作ると、そこから最低でも 2〜3 週間は公開できない。**
アカウント作成とテスター確保だけは、実装の初日から並行して進める。

### テスター 12 人をどう集めるか

| 方法 | 備考 |
|---|---|
| 知人・家族 | 最も確実。Google アカウント（Gmail アドレス）が必要。**Android 端末でなくてもオプトインはできるが、実際に使ってもらう方が有益** |
| 開発者コミュニティの相互テスト | 「テスター募集」の相互協力コミュニティが複数存在する |
| メーリングリストで管理 | Play Console にテスターの Gmail アドレスを登録する方式が管理しやすい |

> **本アプリは実際に毎朝使ってもらえると、そのまま実地テストになる。**
> 「寝坊防止に困っている知人」を優先的に誘うと、テストとフィードバックを兼ねられる。

## 14.2 アカウント作成でユーザーに用意してもらうもの

| # | 項目 | 備考 |
|---|---|---|
| 1 | Google アカウント | 開発用に専用アカウントを作る方が管理しやすい |

## 14.3 アプリの識別情報（確定 / D-022）

| 項目 | 値 |
|---|---|
| アプリ名（ストア表示名） | **タバネアラーム** |
| パッケージ名 | **`io.github.mmmio30.tabanealarm`** |
| 英語表記（将来の海外展開用） | Tabane Alarm |

### 命名の根拠

- 「**束ねる**」= 複数のアラームをグループにまとめるという本アプリの中核概念そのもの
- 「アラーム」を含むため、ストア内検索で見つけてもらえる
- 造語なので、既存アプリに埋もれず指名検索できる
  （「グループアラーム」「アラームプラス」など、グループ機能を持つ既存アプリは既にある）
- 8 文字。Play のアプリ名は 30 文字までなので余裕がある
- キーワードの詰め込みや性能を誇張する表現を含まない（Play のポリシー違反を避ける）

### パッケージ名の根拠

- **公開後は永久に変更できない**ため、最初に確定させる必要がある
- 独自ドメインを持たないため、GitHub アカウント名を使う `io.github.<username>` 形式を採用する
  （プライバシーポリシーを GitHub Pages に置く方針とも整合する）

## 14.4 プライバシーポリシー

**データを一切収集しなくても、URL の掲載は必須。**

| 項目 | 方針 |
|---|---|
| 置き場所 | GitHub Pages（`https://mmmio30.github.io/...`）に静的ページとして公開する |
| 内容 | 「個人情報・利用状況を一切収集せず、外部送信もしない」ことを明記する |
| 根拠 | 本アプリはネットワーク権限を持たない（NFR-4.2 / D-014）ため、正直にそう書ける |
| 作成 | Claude 側で日本語版の草案を用意する |

## 14.5 権限の用途説明（審査で問われる想定）

Play Console で用途を説明する必要がある権限。**説明文は Claude 側で草案を用意する。**

| 権限 | 説明の骨子 |
|---|---|
| `USE_EXACT_ALARM` | 本アプリの中核機能はアラーム（目覚まし）であり、ユーザーが指定した時刻に分単位で正確に鳴らす必要がある |
| `USE_FULL_SCREEN_INTENT` | 就寝中・画面ロック中に起床させるため、ロック画面上に全画面のアラーム画面を表示する必要がある |
| FGS `mediaPlayback` | アラーム音の再生をバックグラウンドで継続するために使用する。Android 17 のバックグラウンド音声制限（4.4b）に適合させるためにも必要 |
| `RECEIVE_BOOT_COMPLETED` | 端末再起動後にアラームの予定を復元するために使用する |

**宣言しない方針の権限**（審査を軽くするため / 9.2）
- `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` → 設定画面を開く導線で代替する
- `READ_MEDIA_AUDIO` → SAF（ファイル選択）で代替する（T-015）
- インターネット権限 → 祝日データを内蔵するため不要（D-014）

## 14.6 targetSdk の要件（確認済み）

| 時期 | 要件 |
|---|---|
| 2026-08-31 以降 | 新規アプリ・アップデートは **API 36（Android 16）以上**が必須（※期限は既に経過） |
| 2027-08 予定 | **API 37（Android 17）以上**が必須になる見込み |

**本アプリの方針（D-023）**: 最初から **targetSdk 37** で開発する。

- 2027 年に強制的な移行作業が発生するのを避けられる
- Android 17 のバックグラウンド音声制限（4.4b）に最初から適合させられる
- Pixel 8a（Android 17）で実機検証できる

> **リスクと退避策**: targetSdk 37 は音声制限が最も厳しい。
> 実機検証（4.4b）で問題が出た場合は、一時的に targetSdk 36 へ下げる。
> ただし 2027 年 8 月までには 37 へ上げる必要がある。

## 14.7 進め方（Claude とユーザーの分担）

| 工程 | 担当 |
|---|---|
| Play Console のアカウント作成・本人確認・支払い | **ユーザー**（代行不可） |
| テスター 12 人の確保・招待 | **ユーザー**（Claude は募集文の草案を用意） |
| プライバシーポリシーの文面作成 | Claude |
| ストア説明文（簡単な説明 / 詳細な説明）の作成 | Claude |
| 権限の用途説明文の作成 | Claude |
| アプリアイコン・スクリーンショット | 実装後。Claude が素案、最終判断はユーザー |
| データセーフティ申告の回答内容 | Claude が草案、入力はユーザー |
| コンテンツレーティングのアンケート | ユーザー（Claude が回答案を用意） |
| 署名鍵の作成とバックアップ | ユーザー（手順は Claude が用意）**紛失すると更新不能になる** |
