# 09. Google Play 公開の要件（D-007 に伴う追加事項）

| 項目 | 内容 |
|---|---|
| ステータス | ドラフト |
| 最終更新 | 2026-09-03 |

> Play 公開を前提にしたことで、**アプリのコード以外に必要な作業**が発生する。
> 特に「9.1 アカウントとテスト要件」は**着手が遅れると公開日がそのまま遅れる**ため、
> 実装と並行して早めに動く必要がある。
> ポリシーは頻繁に変わるため、**各項目は着手時に Play Console の最新表示で必ず再確認する**こと。

---

## 9.1 アカウントとテスト要件（★最優先で確認）

| 項目 | 内容 | 状態 |
|---|---|---|
| 開発者アカウント | Google Play Console の登録（登録料が必要、本人確認あり） | 未着手 |
| 個人 / 組織の別 | **個人アカウントの場合、公開前に「一定人数のテスターによるクローズドテストを一定期間継続する」要件が課される場合がある** | **要確認** |
| 開発者情報の公開 | 個人アカウントでは連絡先情報がストアに公開される場合がある | 要確認 |
| テスター確保 | 上記要件がある場合、**テスターを事前に集める必要がある**（アプリ完成後に慌てないよう先に着手） | 要確認 |

> **これは技術ではなく段取りの問題だが、公開までのリードタイムを最も左右する。**
> 実装開始と同時に Play Console のアカウントを作り、要件の実際の表示を確認しておくことを強く推奨する。

## 9.2 権限に関する申告

本アプリは審査で問われやすい権限を複数使う。

| 権限 | 審査上の論点 | 本アプリの立場 |
|---|---|---|
| `USE_EXACT_ALARM` | 「アラーム / カレンダーが中核機能のアプリ」に限定される。用途外だと公開を拒否される | **アラームアプリそのもの**なので正当。用途説明を用意する |
| `SCHEDULE_EXACT_ALARM` | Android 12–13 向け。ユーザー許可が必要 | 設定画面への誘導 UI を用意する |
| `USE_FULL_SCREEN_INTENT` | Android 14+ ではアラーム / 通話アプリ以外は自動付与されない | アラーム用途として申告。`canUseFullScreenIntent()` で実際の可否を必ず確認 |
| Foreground Service Type | Android 14+ は型の宣言と用途説明が必要。デモ動画を求められる場合がある | `mediaPlayback` / `specialUse` のどちらにするかを決める（→ Q17） |
| `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` | 用途が限定されており、審査で問われやすい | **宣言せず**、設定画面を開くだけの導線（`ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`）で代替する方針 |
| メディア読み取り系 | 音源選択のために `READ_MEDIA_AUDIO` を使うと申告が増える | **使わない**。SAF（`ACTION_OPEN_DOCUMENT`）でファイルを選ばせる（T-015） |
| ネットワーク | 使わなければデータセーフティの申告が最小になる | 祝日データを内蔵する方針（T-011）なら不要 |

**方針**: 権限は「削れるものは徹底的に削る」。審査リスクとプライバシー説明の両方が軽くなる。

## 9.3 ストア掲載に必要な成果物

| 成果物 | 備考 | 状態 |
|---|---|---|
| アプリ名 | 未定（→ Q18） | 未着手 |
| アプリアイコン | 高解像度のマスター画像が必要 | 未着手 |
| フィーチャーグラフィック | ストア上部のバナー画像 | 未着手 |
| スクリーンショット | 複数枚。**グループ一括 ON/OFF と一括作成が伝わる画面**を選ぶ | 未着手 |
| 簡単な説明 / 詳細な説明 | 差別化点（グループ・一括作成・除外日）を前面に出す | 未着手 |
| プライバシーポリシー URL | **データを一切収集しない場合でも掲載が必要**。GitHub Pages 等で公開可能 | 未着手 |
| データセーフティの申告 | 「収集なし / 共有なし」で申告できる想定 | 未着手 |
| コンテンツレーティング | アンケート回答で取得 | 未着手 |
| アプリ署名鍵 | **紛失するとアプリを更新できなくなる**。バックアップ手順を決めておく | 未着手 |

## 9.4 継続的に発生する義務

| 項目 | 内容 |
|---|---|
| targetSdk の追従 | Play は一定期間ごとに新しい targetSdk を要求する。**毎年の対応作業が発生する** |
| ポリシー変更への追従 | 権限・通知・フォアグラウンドサービスの規定は変わりやすい |
| リリーストラック運用 | 内部テスト → クローズドテスト → 製品版の順に上げる |
| 配布形式 | AAB（Android App Bundle）で提出する |
