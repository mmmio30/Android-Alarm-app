## フェーズ C: 実装 — 土台 ＆ クローズドテスト投入版

**この段階のゴールは「MVP 完成」ではなく「クローズドテストに出せる最小限のビルド」。**
14 日間の計測はビルドをアップロードした時点から始まるため、
ここを最速で通過することがリリース日を最も早める（→ `14-play-console-setup.md` 14.1）。

- Android プロジェクトの雛形（Compose / Room / Hilt / Version Catalog）
  - `applicationId = io.github.mmmio30.tabanealarm` / minSdk 26 / targetSdk 37
- `RingDecider` の判定ロジックとユニットテスト 69 件（**UI より先に作る**）
- `AlarmScheduler`（次の 1 件を登録・再計算）
- 鳴動の最小実装（全画面 Activity + Foreground Service + 停止 / スヌーズ）
- **Android 17 のバックグラウンド音声制限の実機検証**（→ `04` の 4.4b）※ 最優先
- アラームの作成・編集・ON/OFF、グループの作成と一括 ON/OFF
- 端末再起動後の復元
- 実機 3 台で E-01〜E-10 を通す（→ `04` の 4.7b）

> ここが動けば「アラームアプリとして成立する」最低ラインに到達し、
> **クローズドテストを開始できる**。以降の機能は 14 日の待機期間中に配信する。
