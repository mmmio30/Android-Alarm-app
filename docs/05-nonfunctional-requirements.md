# 05. 非機能要件

| 項目 | 内容 |
|---|---|
| ステータス | ドラフト |
| 最終更新 | 2026-09-03 |

## NFR-1. 信頼性（最優先）

| ID | 要件 |
|---|---|
| NFR-1.1 | 設定したアラームは、端末再起動・アプリ更新・タイムゾーン変更をまたいでも鳴ること |
| NFR-1.2 | アプリがクラッシュしても、次回起動時に整合性を回復できること（起動時に必ず再計算） |
| NFR-1.3 | 音源が失われた場合でも無音にならず、既定音にフォールバックすること |
| NFR-1.4 | 「鳴らない可能性がある状態」（権限不足・DND・音量 0・電池最適化）を検出し、ユーザーに警告すること |
| NFR-1.5 | 日次セーフティネットにより、スケジュール登録漏れを 24 時間以内に自己修復すること |

## NFR-2. 操作性

| ID | 要件 |
|---|---|
| NFR-2.1 | グループの一括 ON/OFF は**ホーム画面から 1 タップ**で到達できること |
| NFR-2.2 | 「6:00 から 5 分おきに 6 個」の作成が **30 秒以内**で完了できること |
| NFR-2.3 | 「明日鳴るかどうか」を**アプリ内 2 タップ以内**で確認できること |
| NFR-2.4 | 鳴動時の「停止」は、寝ぼけていても押せる十分な大きさであること |
| NFR-2.5 | 誤操作でアラームを削除した場合、取り消し（Undo）できること |

## NFR-3. 性能

| ID | 要件 |
|---|---|
| NFR-3.1 | アラーム 200 件 / 除外日 500 件の状態でも、一覧表示が 500ms 以内に完了すること |
| NFR-3.2 | 「次の鳴動時刻」の全件再計算が 100ms 以内で完了すること |
| NFR-3.3 | アラーム発火から音が鳴り始めるまで 1 秒以内であること |
| NFR-3.4 | 待機中のバッテリー消費が実質ゼロであること（常駐サービスを持たない設計） |

## NFR-4. データ

| ID | 要件 |
|---|---|
| NFR-4.1 | すべてのデータは端末内に保存し、外部へ送信しないこと |
| NFR-4.2 | ネットワーク権限を持たないこと（D-014 により祝日データを内蔵するため確定） |
| NFR-4.3 | 設定を JSON でエクスポート / インポートでき、機種変更時に復元できること |
| NFR-4.4 | DB スキーマ変更時は Room のマイグレーションを必ず記述し、データを失わないこと |

## NFR-5. 対応環境

| ID | 要件 |
|---|---|
| NFR-5.1 | minSdk 26（Android 8.0）以上 [仮] |
| NFR-5.2 | 日本語 UI を提供する。英語対応は将来検討 |
| NFR-5.3 | ライト / ダークテーマに対応する |
| NFR-5.4 | 端末のフォントサイズ拡大設定でレイアウトが崩れないこと |
| NFR-5.5 | 縦画面のみ対応（横画面は将来検討） |

## NFR-6. 保守性

| ID | 要件 |
|---|---|
| NFR-6.1 | 鳴動判定ロジック（`willRing`）は Android 依存を持たない純粋関数とし、ユニットテスト可能にすること |
| NFR-6.2 | 時刻取得は `java.time.Clock` を DI し、テストで任意の日時を再現できること |
| NFR-6.3 | 祝日データはコードから分離したリソースとして持ち、更新しやすくすること |

## NFR-7. プライバシー / 配布

| ID | 要件 | 状態 |
|---|---|---|
| NFR-7.1 | 個人情報を収集しない | 確定 |
| NFR-7.2 | 広告を表示しない | 仮 |
| NFR-7.5 | プライバシーポリシーを公開し、ストアに URL を掲載する | 確定 |
| NFR-7.6 | 必要最小限の権限のみを宣言する（メディア読み取り権限・ネットワーク権限を持たない） | 仮 |
| NFR-7.3 | 課金機能を持たない | 仮 |
| NFR-7.4 | **Google Play で一般公開する**（D-007）。関連要件は `09-play-release.md` を参照 | 確定 |
