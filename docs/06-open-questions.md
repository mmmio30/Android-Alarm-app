## A. 設計フェーズに入る前に知りたいこと

### Q14. 動作確認に使える実機はあるか？（機種名 / Android バージョン）
エミュレータだけだと OEM 独自の省電力（Xiaomi / OPPO / vivo / Huawei / Samsung 等）を検証できず、
**「一部の機種でだけ鳴らない」という最も厄介な不具合を見逃す。**
minSdk の決定（Q13）にも影響する。

### Q19. Google Play Console のアカウントは既にあるか？
無い場合、登録と本人確認に日数がかかることがあり、
さらに個人アカウントには公開前のテスト要件が課される可能性がある（→ `09-play-release.md` 9.1）。
**アプリ完成後に着手すると公開がその分だけ遅れる**ため、実装と並行して進めたい。

### Q18. アプリ名は何にするか？
ストア掲載名とパッケージ名（`com.xxx.yyy`）の決定に必要。
パッケージ名は**公開後に変更できない**ため、実装の最初に決める必要がある。
仮でもよいので方向性（日本語名 / 英語名 / 造語）を決めたい。

### Q13. minSdk はいくつにするか？
| | 選択肢 |
|---|---|
| A | 26（Android 8.0）。ほぼ全端末をカバー（推奨） |
| B | 29 / 31 など。実装は楽になるが対象端末が減る |

Q14 の回答（手元の端末）次第で調整する。特に希望が無ければ A で進める。

### Q21. 内蔵する祝日データは何年分にするか？（D-014）
| | 選択肢 |
|---|---|
| A | 現在年 + 3 年分（アプリを 3 年放置しても動く。推奨） |
| B | 現在年 + 5 年分以上 |
| C | 過去分も含める（過去のスケジュールを振り返る用途があれば） |

長く入れるほど法改正で誤ったデータを持つリスクも増えるが、
ユーザーが手動で修正できる（FR-4.3.6）ので実害は小さい。

## B. 仕様の細部（設計フェーズで決めればよい）

### Q20. 深夜アラーム（例: 深夜 2:00）の「日付」の扱いは直感に合うか？
現案では 2:00 のアラームは「その日の 2:00」として扱う。
つまり「金曜の夜更かし用に 2 時のアラーム」を設定したい場合、
**土曜にチェックを入れる**必要がある。

| | 選択肢 |
|---|---|
| A | 現案どおり。ただし 0:00〜4:00 台のアラームには UI で「※これは土曜の未明です」と補足を出す（推奨） |
| B | 「前日の夜として扱う」モードをアラームごとに持つ |

### Q8. 高度な繰り返し（隔週 / N 日おき / シフト勤務）は必要か？
| | 選択肢 |
|---|---|
| A | 不要。除外日の一括登録で代替する（推奨） |
| B | 必要（どういう勤務パターンかを教えてほしい） |

### Q10. イヤホン接続時に「常にスピーカーから鳴らす」オプションは必要か？
イヤホンをしたまま寝る習慣があるかどうかで要否が変わる。

### Q17. 鳴動中のフォアグラウンドサービスの型をどちらにするか？
`mediaPlayback` / `specialUse` のいずれか。技術的にはどちらでも動く。
**Play 審査での通りやすさで決めたい**ため、実装直前に Play Console の最新表示を見て判断する。
→ 現時点では判断を保留し、実装フェーズで決定する。

### Q16. 普段使っているアラームアプリと、その中で気に入っている点は？

逆に「ここが嫌い」も同じくらい有用。
