## 最優先（これが決まらないと設計が固まらない）

### Q1. 配布方法は？ Google Play 公開 / 自分用（APK 直接インストール）
**影響**: 権限の申告手続き、プライバシーポリシー、targetSdk の追従義務、
アプリアイコン・ストア掲載素材、Foreground Service Type の選択、更新運用。
自分用なら省ける工程が多く、開発速度が上がる。

- [ ] A: 自分（と身内）用。Play には出さない
- [ ] B: 最初は自分用、将来 Play 公開も視野に入れる
- [ ] C: 最初から Play 公開を前提に作る

---

### Q2. 「グループ内で 1 つ解除したら、その日の残りを自動スキップ」を入れるか？（FR-2.4.1）
**影響**: 本アプリの差別化の中心になる可能性がある。
5 分おきアラームの最大の不満（起きた後も鳴り続ける）を解決する。
実装は「その日限りのスキップ」テーブル + 再計算だけで、コストは中程度。

- [ ] A: 入れる。グループの既定を ON にする（推奨）
- [ ] B: 入れるが既定は OFF
- [ ] C: 入れない（純粋に一括 ON/OFF だけでよい）

---

### Q3. グループ設定の「継承」を入れるか？（FR-2.3）
**影響**: 音・スヌーズ・バイブをグループ側で一元管理し、
個別アラームは必要なときだけ上書きする方式。
これが無いと「10 個作った後に音を変える」が 10 回の編集になる。
UI が一段複雑になるのがデメリット。

- [ ] A: 入れる（推奨）
- [ ] B: 入れない。グループは ON/OFF と除外日だけを持ち、音などは常に個別設定
- [ ] C: 入れないが「グループ内の全アラームに設定を一括適用」ボタンで代替する

## 機能に関する判断

### Q5. 解除ミッション（計算問題 / シェイク / タイピング）は入れるか？（FR-5.11）
- [ ] A: MVP に入れる（計算問題のみ）
- [ ] B: MVP 外。将来追加
- [ ] C: 不要

### Q6. 「除外日」と「予約日」が同じ日に重なったらどちらを優先するか？（3.3）
- [ ] A: 除外日が勝つ = 鳴らない（推奨。「有給なので全部止めたい」が直感的）
- [ ] B: 予約日が勝つ = 鳴る（「この日だけは絶対起きたい」を優先）

### Q7. 祝日データの持ち方は？（FR-4.3.6）
- [ ] A: アプリに内蔵（オフライン完結・ネット権限不要・推奨）。法改正時はアプリ更新で対応
- [ ] B: ネットから年 1 回取得（内閣府 CSV 等）。常に最新だがネット権限が必要になる
- [ ] C: A を基本とし、ユーザーが手で祝日を追加・削除できるようにする

### Q8. 高度な繰り返し（隔週 / N 日おき / シフト）は必要か？（FR-1.8）
- [ ] A: 不要。除外日の一括登録で代替する（推奨）
- [ ] B: 必要（具体的なパターンを教えてほしい）

### Q9. 一括作成時の「エスカレーション」（後半ほど音量大 / 音を変える）は必要か？（FR-3.9）
- [ ] A: 不要
- [ ] B: 音量だけ上げる
- [ ] C: 音量 + 解除ミッションの難易度も上げる

### Q10. イヤホン接続時に「常にスピーカーから鳴らす」オプションは必要か？（4.4）

### Q11. ウィジェット / クイック設定タイルはどの段階で入れるか？（FR-8）
グループ一括 ON/OFF との相性が良い。

- [ ] A: MVP に入れる
- [ ] B: MVP 外。まずは `BOOT_COMPLETED` のみ（推奨）

### Q13. minSdk はいくつにするか？

- [ ] B: 29 / 31 など、より新しく。実装は楽になるが対象端末が減る
- [ ] C: 手持ちの端末に合わせる → **使用予定の端末と Android バージョンを教えてほしい**

### Q14. 開発・動作確認に使える実機はあるか？（機種 / Android バージョン）
エミュレータだけだと OEM 省電力の検証ができない。
