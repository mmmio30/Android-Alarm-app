# 07. 決定ログ

確定した決定事項を時系列で記録する。
「なぜそう決めたか」を残すことで、後から蒸し返さずに済むようにする。

## 確定事項

| ID | 日付 | 決定事項 | 理由 |
|---|---|---|---|
| D-001 | 2026-09-03 | 対象プラットフォームは Android のみ | 要望どおり。iOS はスコープ外 |
| D-002 | 2026-09-03 | 差別化軸は「アラームの管理コストの削減」の 1 点に絞る | 音源の充実や睡眠計測など既存アプリとの機能競争はしない |
| D-003 | 2026-09-03 | コア価値は ①グループ一括 ON/OFF ②一括作成 ③予約日・除外日の事前登録 の 3 つ | 要望として明示されたもの |
| D-004 | 2026-09-03 | 音・バイブ・スヌーズ・祝日自動 OFF は「既存アプリ同等」を目標とし、独自性を求めない | 要望どおり |
| D-005 | 2026-09-03 | 睡眠トラッキング・天気読み上げ・SNS 連携はスコープ外 | 差別化軸から外れるため |
| D-006 | 2026-09-03 | クラウド同期は行わない。バックアップは JSON エクスポートで代替 | 個人利用前提、実装コスト過大 |
| D-007 | 2026-09-03 | **最初から Google Play 公開を前提に設計・実装する** | ユーザー判断（Q1）。権限の用途申告、プライバシーポリシー、ストア素材、targetSdk 追従、テスト要件を初期段階から織り込む → `09-play-release.md` |
| D-008 | 2026-09-03 | **「グループ内のいずれか 1 つを停止したら、その日の残りを自動スキップ」を実装し、グループ既定を ON にする** | ユーザー判断（Q2）。5 分おきアラームの最大の不満（起きた後も鳴り続ける）を解決する、本アプリ最大の差別化機能 |
| D-009 | 2026-09-03 | **無操作による自動停止では D-008 のスキップを発動させない** | 無操作で鳴り止んだ = まだ寝ている。明示的な停止操作のみを起床とみなす |
| D-010 | 2026-09-03 | **音・音量・バイブ・スヌーズ等の設定はグループが保持し、アラームは「継承」または「個別上書き」を選べる** | ユーザー判断（Q3）。一括作成した 10 個の設定を後から一括変更できないと、一括作成の価値が失われるため |
| D-011 | 2026-09-03 | **グループ ON/OFF と個別 ON/OFF は独立に保持し、AND で実効判定する（マスタースイッチ方式）** | 一括代入方式だと「5 個中 3 個だけ ON」という状態がグループ再 ON 時に失われるため。D-010 の前提でもある |
| D-012 | 2026-09-03 | **要件 → 設計（画面 / DB / アーキテクチャ）を文書で固めてから実装に入る** | ユーザー判断（Q15）。手戻りを減らす |

## 仮決定（合意が取れ次第、上の表へ昇格）

| ID | 仮決定 | 根拠 | 対応する質問 |
|---|---|---|---|
| T-001 | アラームは最大 1 つのグループに所属する（多対多にしない） | 多対多だと ON/OFF の意味が説明不能になる | — |
| T-004 | 除外日と予約日は同一テーブル（DateRule）で表現する | UI とロジックを共通化できる | — |
| T-005 | 除外日はアプリ全体 / グループ / アラームの 3 階層で持ち、OR で判定する | 「今週は全休」「平日グループだけ休み」を両方表現できる | — |
| T-006 | 除外日は予約日より優先する（重なったら鳴らない） | 「休みなので止めたい」が最も直感的 | Q6 |
| T-007 | AlarmManager には常に「次の 1 件」だけを登録し、発火ごとに再計算する | 大量アラームでもシステム制限・電池消費を回避できる | — |
| T-008 | `setAlarmClock()` を使う | Doze を貫通する唯一の確実な手段 | — |
| T-010 | 「実効スケジュールのプレビュー」を MVP に含める | 設定要素が多く、鳴るかどうかをユーザーが推論できないため | — |
| T-011 | 祝日データはアプリ内蔵とし、ネットワーク権限を持たない | オフライン完結・プライバシー保護・実装が単純 | Q7 |
| T-012 | minSdk 26 / 単一モジュール構成 / Compose + Room + Hilt | 個人開発規模に対して妥当 | Q13 |
| T-013 | 一括作成は 1 回あたり最大 50 件まで | 際限なく作られると UI と再計算が破綻するため | — |
| T-014 | 一括作成したアラームは自動的に 1 グループにまとめる | グループ機能と一括作成は本質的にセットのため | — |
| T-015 | 音源選択は SAF（`ACTION_OPEN_DOCUMENT`）で行い、メディア読み取り権限を要求しない | 権限を減らすと Play 審査もプライバシー説明も単純になる（D-007 と整合） | — |
| T-016 | 選択した音源はアプリ内ストレージにコピーして保持する | URI 権限の失効・ファイル削除で無音になる事故を防ぐ | — |
